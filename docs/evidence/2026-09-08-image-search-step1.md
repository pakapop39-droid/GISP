## ข้อสรุปเพื่อดำเนินงานต่อ

GISP มีรูปสินค้าเพียงพอให้เริ่มทำระบบค้นหาภาพ และฐานข้อมูลรองรับ vector อยู่แล้ว
ในการทดลอง CLIP ViT-B/32 แบบ q8 ให้ผลรวมดีกว่า ViT-B/16 แบบ q8 จึงเลือก B/32
เป็น baseline สำหรับทดลองต่อ (512 dimensions) ยังไม่ล็อกเป็นโมเดลที่จะเปิดให้ใช้งานจริง

ภาพย่อของรูป Catalog ค้นเจอสินค้าเดิมได้ดี แต่รูปสินค้าในห้อง/พื้นหลังต่างจากรูปหลัก
ยังมีข้อผิดพลาดชัดเจน ส่วนเกณฑ์ “สินค้าคล้ายที่ยอมรับได้” ต้องมีผู้ตรวจให้คะแนน
และยังไม่มีชุดภาพที่ยืนยันว่าไม่มีสินค้าคล้ายในระบบ จึงยังรับรองเป้าหมายคุณภาพไม่ได้

ยังไม่สร้าง API ค้นหาจริง ไม่เปลี่ยน schema/สินค้า และไม่ deploy งาน Image Search

## วิธีทดลองและผล

เลือก 50 สินค้าแบบวนกระจายหมวดและเรียง SKU ก่อนดูคะแนน แบ่งสินค้าคนละชุด
สำหรับ calibration และ holdout ชุดละ 25 สินค้า วิธีนี้ครอบคลุมหมวดเล็ก แต่ไม่ใช่การสุ่ม
ตามสัดส่วนของ Catalog ทั้งหมด และยังมีสินค้ารูปแบบ/ตระกูลใกล้กันข้ามชุดได้

ใช้คำค้น 97 ภาพ: ภาพย่อ/บีบอัด 50 ภาพ และภาพอีกไฟล์จากสินค้าเดียวกัน 47 ภาพ
แยกภาพอีกไฟล์ออกจาก gallery ของสินค้านั้น Gallery ใช้เพียงภาพหลักสินค้าแต่ละรายการ
ภาพอีกไฟล์เป็นตัวแทนเบื้องต้น อาจเป็นคนละสี ภาพรายละเอียด หรือคนละมุม ไม่ใช่ภาพถ่ายใหม่จากลูกค้า

| โมเดล local CPU, q8 | ภาพย่อ: เจอชิ้นเดิม Top 5 (holdout) | ภาพอีกไฟล์: เจอชิ้นเดิม Top 10 (holdout) | p95 บนเครื่อง |
| --- | --- | --- | --- |
| CLIP ViT-B/32 | 24/25 = 96% | 16/24 = 66.7% | 38.6 ms |
| CLIP ViT-B/16 | 22/25 = 88% | 15/24 = 62.5% | 61.7 ms |

Calibration: B/32 ภาพย่อ Top 5 = 24/25, ภาพอีกไฟล์ Top 10 = 14/23;
B/16 ภาพย่อ Top 5 = 20/25, ภาพอีกไฟล์ Top 10 = 14/23
ไม่พบ query bytes ซ้ำกับ gallery bytes แบบตรงตัว แต่ภาพใกล้ซ้ำอาจยังทำให้ผลสูงขึ้นได้
ตัวอย่าง holdout มีจำนวนน้อย และถูกใช้เปรียบเทียบโมเดลแล้ว จึงต้องมีชุดประเมินใหม่ก่อนรับงานจริง

การทดลองเสริมหลังดูผล: หากผู้ใช้เลือกหมวดถูกต้อง B/32 ค้นชิ้นเดิม Top 10 ได้ 17/24,
B/16 ได้ 16/24 ไม่ใช่ผลการทายหมวดอัตโนมัติและยังไม่ใช่ผลยืนยันเกณฑ์สินค้าคล้าย

เวลาเป็นการอ่านรูปที่เตรียมไว้ ประมวลผล embedding และจัดอันดับบนเครื่อง
Intel Core Ultra 7 255H, RAM 15.4 GiB, ONNX CPU 4 threads
ทดสอบเวลาใหม่โดยรันโมเดลทีละตัวหลังโหลดเสร็จ ใช้คำค้น 20 ครั้งที่ไม่ใช้ embedding cache
ไม่รวมการอัปโหลด เครือข่าย ฐานข้อมูล Auth และ Signed URL จึงยังยืนยัน hosted p95 ≤ 8 วินาทีไม่ได้

## สิ่งที่เรียนรู้จากภาพที่พลาด

- โต๊ะข้างในภาพห้องถูกจัดเป็นเก้าอี้ในผลอันดับแรก; ตู้ข้างเตียงถูกดึงไปใกล้ภาพเตียง
  สอดคล้องกับข้อสังเกตว่าบริบทห้องมีผลต่อ embedding แต่ยังไม่ได้ทำการทดลองแยกสาเหตุ
- บางครั้งผลแรกเป็นเฟอร์นิเจอร์ประเภทเดียวกันและดูคล้าย แม้ค้นไม่เจอรหัสเดิม
  คะแนน same-product retrieval จึงใช้แทน human-rated similarity ไม่ได้
- สินค้ารูปหลักซ้ำต้องแสดง SKU และรายละเอียดแยก ห้ามรับรองว่ายืนยันรุ่นจากภาพได้
- เสนอทดลองให้ผู้ใช้ครอบเฉพาะสินค้า และใช้หลายมุมใน gallery รอบถัดไป
  ต้องใช้ภาพคำค้นที่กันออกจาก gallery เสมอเพื่อไม่ให้ผลทดสอบสูงเกินจริง

## หลักฐานและการตรวจงาน

- รัน syntax check และ ESLint สำหรับสคริปต์ทดลองผ่าน
- รัน `validate.mjs` ผ่าน: inventory reconciliation, แยกสินค้า calibration/holdout,
  ภาพ query ไม่ใช่ไฟล์ gallery ของสินค้านั้น, vector finite/normalized, ผลเรียงถูก/ไม่ซ้ำสินค้า,
  ไฟล์รูปในรายงานมีจริง, ไม่อ้าง threshold/API test ที่ไม่ได้ทำ, การคำนวณราคา และข้อมูลในหน้า review
- เปิดรายงานใน browser จริง รูป 11/11 โหลดได้ เปลี่ยนตัวอย่างได้
  Desktop และ 390×844 ไม่มี horizontal overflow
- ไม่รัน application build/full regression เพราะเพิ่มเฉพาะสคริปต์ทดลองและเอกสาร ไม่มีการแก้โค้ดแอป

ไฟล์ local ที่สร้างไว้:

- `output/image-search-spike/review.html` — เปิดดู query และ Top 10 สลับโมเดล/ชุดภาพ และดาวน์โหลดคะแนนตรวจ
- `output/image-search-spike/dataset.json` — gallery/query และรายละเอียดภาพที่ตรวจ
- `output/image-search-spike/clip-vit-base-patch32/results.json` และ `clip-vit-base-patch16/results.json`
- `output/image-search-spike/costs.json` — สูตร/สมมติฐานค่าใช้จ่าย
- `output/image-search-spike/failure-contact.png` — ตัวอย่างกรณีที่พลาดเพื่อวิเคราะห์
- `output/image-search-spike/review-desktop.png` และ `review-mobile.png` — ภาพตรวจหน้า report

รูปและรายละเอียด private storage อยู่ใน output ที่ Git ignore ไว้
รายงานคะแนนจากผู้ตรวจในหน้า HTML เป็น exploratory review ไม่ใช่ blind evaluation ที่กำหนดคำตอบล่วงหน้า

## งานที่ยังเหลือ

ขั้นตอนที่ 1 ยังเหลือ 2 งานย่อย:

1. เติมภาพถ่ายจริง/ภาพที่ไม่มีสินค้าคล้าย กำหนดคำตอบที่ยอมรับได้โดยผู้ตรวจ
   แล้ววัด similarity และปรับเกณฑ์ไม่พบสินค้าบนชุด calibration ก่อนวัดชุดใหม่ที่แยกไว้
2. ทดลองบริการ image embedding อีกทางเลือกเมื่อมีบัญชี/API key พร้อมใช้
   เปรียบเทียบคุณภาพ ความเร็ว และต้นทุนครบ แล้วสรุปโมเดล/วิธีให้บริการขั้นสุดท้าย

หลังจากนั้นจึงเข้าสู่ขั้นตอนที่ 2 ตามแผน ไม่ล็อก dimension/schema จริงก่อนตัดสินใจ
Image Search รวมยังเหลือ 4 ขั้นตอนหลัก โดยขั้นตอนแรกเสร็จบางส่วน
Slice 13 เดิมยังคงเหลือ Human UAT และ Owner Sign-off 1 ขั้นตอนตามหลักฐานเดิม
