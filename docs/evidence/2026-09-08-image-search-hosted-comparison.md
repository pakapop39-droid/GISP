# Image Search — ทดลองบริการ AI จริงหลังยอมรับงบประมาณ

วันที่: 8 กันยายน 2569
สถานะ: การเปรียบเทียบบริการ AI เสร็จ; ขั้นตอนที่ 1 เหลือชุดภาพจริงและการตรวจความคล้าย
หลักฐานตัวเลข: [ผล API และค่าใช้จ่าย](2026-09-08-image-search-hosted-comparison.json)

## ผลลัพธ์

เลือก `voyageai/voyage-multimodal-3.5` ผ่าน OpenRouter เป็นตัวหลักสำหรับพัฒนารุ่นทดลองต่อ
ใช้ embedding ขนาด 1,024 ค่าแบบ float และแยกข้อมูลจาก CLIP เดิม ไม่เปรียบเทียบข้ามโมเดล
การเลือกครั้งนี้อาศัยคุณภาพ/ต้นทุนจากชุด Catalog; การรับรองก่อนเปิดใช้ยังต้องผ่านภาพจริงและกรณีไม่พบ

| ชุดวัดผลที่กันไว้ | CLIP B/32 เดิม | Voyage |
| --- | ---: | ---: |
| ภาพย่อ: เจอสินค้าชิ้นเดิมใน 5 อันดับแรก | 24/25 (96%) | 25/25 (100%) |
| ภาพอีกไฟล์: เจอสินค้าชิ้นเดิมใน 10 อันดับแรก | 16/24 (66.7%) | 21/24 (87.5%) |
| ภาพอีกไฟล์: เจอสินค้าชิ้นเดิมอันดับแรก | 9/24 | 14/24 |

ใช้ gallery 634 สินค้า และ query 97 ภาพจาก 50 สินค้า ชุดเดียวกับ baseline เดิม
รวมภาพซ้ำตาม hash เพื่อลดการเรียก API โดยผลยังแสดงสินค้าแยก SKU
Calibration ของ Voyage: ภาพย่อ Top 5 = 24/25; ภาพอีกไฟล์ Top 10 = 18/23
การเปรียบเทียบหลายโมเดลใช้ holdout เดิม จึงต้องมีชุดภาพใหม่ก่อนรับรองคุณภาพขั้นสุดท้าย

## ค่าใช้จ่ายและเวลา

- การเรียกที่สำเร็จ 68 requests ประมวลผลรวม 744 image inputs
  รวมภาพสินค้า/คำค้นและการวัดเวลา 20 ครั้ง ไม่ได้คิดว่า 68 requests เท่ากับ 68 คำค้นของผู้ใช้
- ผล response รายงานค่าใช้จ่ายรวม **$0.2437521408** ทุก response ที่สำเร็จมีข้อมูล cost
- จัดสรรเพดานทดลอง $1 และกันวงเงินแบบเผื่อสูงสุดก่อนแต่ละคำขอรวม $0.9685
  ยอดกันวงเงินเป็นกลไกสคริปต์ ไม่ใช่ยอดเรียกเก็บ
- เวลาเรียก AI รวม network และจัดอันดับบนเครื่อง: median **0.622 วินาที**, p95 **0.684 วินาที**, n=20
- เวลานี้ยังไม่รวมอัปโหลดจากมือถือ, Auth, SQL/RLS, Signed URL และโหลดผู้ใช้หลายคนบนเว็บจริง
  จึงไม่ใช้ยืนยัน hosted acceptance ของแอปที่ยังไม่ได้สร้าง

รูปที่ส่งย่อไม่เกิน 768×768 ตัด metadata ผ่านการเตรียมรูปเดิม
อัตราภาพที่บริการรายงานสอดคล้องกับ $0.60 ต่อพันล้านพิกเซล และตัวอย่างคำค้น 10,000 ภาพ
ขนาดดังกล่าวประมาณ $3.54 เฉพาะค่า inference ก่อนค่าระบบอื่น/ค่าธรรมเนียมการเติมเครดิต.
[ราคาโมเดลบน OpenRouter](https://openrouter.ai/voyageai/voyage-multimodal-3.5)

## การเชื่อมต่อและขอบเขตข้อมูล

ผู้ใช้ยืนยันว่ารับงบประมาณและให้ดำเนินงานต่อแล้ว
ตรวจพบว่า InsForge มี project Model Gateway key อยู่เดิมผ่าน `ai overview`
จากนั้นใช้ `npx -y @insforge/cli ai setup` เขียนคีย์ไว้ฝั่ง server ใน `.env.local` ที่ Git ignore
ไม่สมัครบัญชีใหม่ ไม่เพิ่มช่องทางชำระเงิน และไม่เปลี่ยน production

แก้ความเข้าใจจากรอบก่อน: การไม่พบ key ใน local env/รายการ secrets ไม่ได้หมายความว่า
Model Gateway ของโครงการไม่มี key; ต้องตรวจผ่านคำสั่ง AI โดยตรงด้วย

ยืนยันโมเดลรับ image input ด้วย live `/api/v1/embeddings/models` และ endpoint metadata
ส่งเฉพาะ bytes ของรูปสินค้า Catalog ในชุดที่เตรียมไว้ ไม่ส่ง API key ของ InsForge,
private storage URL, ข้อมูลโรงงาน/ต้นทุน หรือรูปคำขอส่วนตัวของสมาชิกให้โมเดล

คำขอจริงระบุ `only: ['voyageai']`, `allow_fallbacks: false`, `data_collection: 'deny'`
เพื่อใช้ provider ที่ระบุและกรองการใช้ข้อมูลฝึกโมเดล
การ probe แรกที่ระบุ `zdr: true` ได้ HTTP 404 เนื่องจาก Voyage ไม่มี route ตามเงื่อนไขนั้น
การทดสอบจึงใช้ no-training routing โดยไม่ได้แก้ privacy settings ของบัญชี
**ไม่ได้ยืนยัน zero data retention ของ provider**; การลบภาพชั่วคราวใน GISP ภายใน 24 ชั่วโมง
ไม่ใช่คำรับรองระยะเก็บข้อมูลของผู้ให้บริการ AI.
[นโยบาย OpenRouter](https://openrouter.ai/docs/guides/features/zdr)

## สิ่งที่ส่งมอบและการตรวจ

- `scripts/image-search-spike/benchmark-voyage.mjs`: smoke ก่อน batch, ตรวจมิติ/ค่าตัวเลข,
  cache ตาม hash/รุ่นโมเดล, บันทึก response cost และกันงบก่อนส่ง; ไม่ replay คำขอที่ผลไม่แน่นอนอัตโนมัติ
- `output/image-search-spike/voyage-multimodal-3.5/`: vectors, results, summary และ ledger แบบ local
- ปรับ `build-review.mjs` และ `review.html` ให้เทียบ 3 โมเดล แยกเวลาบนเครื่อง/ผ่าน network
- ปรับ `validate.mjs --require-hosted` ให้ตรวจข้อมูลครบทั้ง 3 โมเดล, มิติ 512/1024,
  budget guard, receipt reconciliation และ no-training policy ที่ส่งจริง
- ESLint, syntax check และ benchmark validation ผ่าน
- Browser report แสดงผลครบ 3 โมเดล รูปโหลดครบ และไม่ล้นหน้าจอ Desktop/390px
- ไม่มีการเพิ่ม API ของแอป, migration, การเขียนสินค้า หรือ deployment ในรอบนี้

## งานที่เหลือเพื่อปิดขั้นตอนที่ 1

เหลือ **1 งานย่อย: ชุดภาพถ่ายจริงพร้อมคำตอบจากผู้ตรวจ**

ต้องมีภาพจากการใช้งานจริง ทั้งรูปสินค้าที่มีใน GISP, สินค้าที่อาจมีรุ่นใกล้เคียง และภาพที่ไม่มี
สินค้าคล้ายเพียงพอ พร้อมรายการสินค้าที่ยอมรับได้หรือระบุว่าไม่ควรคืนผล
ใช้ชุดหนึ่งปรับเกณฑ์ และกันอีกชุดไว้ประเมินโดยไม่ใช้ปรับโมเดล
ยังไม่ตั้ง threshold จากคะแนนเชิงบวกอย่างเดียว และไม่อ้างว่า 87.5% คือความแม่นยำภาพคล้ายทั่วไป

แนวทางให้ผู้ใช้ส่งภาพ: [คำแนะนำชุดทดสอบ](../uat/IMAGE-SEARCH-REAL-PHOTO-TEST.md)
เมื่อได้ข้อมูลนี้จึงปิด gate คุณภาพขั้นตอนที่ 1 และเริ่ม backend/schema ตามแผน

Image Search รวมยังเหลือ **4 ขั้นตอนหลัก**: ปิดการทดลองคุณภาพ, ระบบค้นหาหลังบ้าน,
หน้าค้นหาภาพ และทดสอบรับงาน
