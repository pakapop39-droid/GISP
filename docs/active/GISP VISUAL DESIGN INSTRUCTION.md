## 3. คำจำกัดความสไตล์ GISP

> **GISP Quiet Architectural Operations — ความเรียบหรูแบบแกลเลอรีเฟอร์นิเจอร์ ผสานกับความแม่นยำของระบบบริหารงาน**

บุคลิกที่ต้องการ:

- Modern แต่ไม่ตามกระแสจนล้าสมัยเร็ว
- Minimal แต่ไม่ตัดข้อมูลที่จำเป็นต่อการตัดสินใจ
- Luxury จากสัดส่วน ภาพ วัสดุ และ Typography ไม่ใช่จากการใส่ทองหรือเงาจำนวนมาก
- Calm ขณะดูสินค้า แต่ Precise ขณะทำธุรกรรม
- Editorial ใน Member Portal และ Operational ใน Back Office
- เชื่อถือได้ โปร่งใส และไม่ดูเหมือน Marketplace ราคาถูก

## 4. หลักการออกแบบบังคับ

### 4.1 ให้เนื้อหาเป็นพระเอก

- ใช้ภาพสินค้า วัสดุ และโครงการที่มีคุณภาพเป็น Visual Focus
- หนึ่งหน้าควรมีลำดับความสำคัญชัดเจน ไม่วาง Card ที่เด่นเท่ากันเต็มหน้าจอ
- ใช้พื้นที่ว่างเพื่อแบ่งเรื่อง ไม่ใช้กรอบหลายชั้น
- ลดข้อความตกแต่งที่ไม่ช่วยการตัดสินใจ

### 4.2 เรียบหรูจากระบบ ไม่ใช่ของประดับ

- ใช้เส้น 1px, ระยะห่างที่สม่ำเสมอ และ Alignment ที่แม่นยำ
- ไม่ใช้ Gradient, Glassmorphism, Neon, 3D Icon หรือเงาหนัก
- ไม่ทำทุกส่วนเป็น Card มุมมน
- ไม่ใช้ Pill Button เป็นปุ่มหลัก
- สี Accent ใช้เพื่อสถานะหรือการกระทำสำคัญเท่านั้น

### 4.3 ความชัดเจนสำคัญกว่าการเลียนแบบเว็บอ้างอิง

- หน้าธุรกรรมต้องอ่านยอดเงิน สถานะ ผู้รับผิดชอบ และขั้นตอนถัดไปได้ทันที
- หน้าหลังบ้านไม่ใช้ Hero Image ขนาดใหญ่จนเบียดงาน
- ตารางและ Form ต้องมี Label ชัดเจน ห้ามใช้ Placeholder แทน Label
- พื้นที่ว่างสามารถลดลงในหน้าทำงานที่มีข้อมูลมาก แต่ยังต้องรักษาจังหวะและ Alignment เดิม

### 4.4 Member และ Back Office ต้องรู้สึกว่าเป็นระบบเดียวกัน

- ใช้ Font, Color Token, Button, Form, Divider, Status และ Motion ชุดเดียวกัน
- Member Portal เน้นภาพและการเลือกสินค้า
- Back Office เน้น Action Required, ตาราง, Timeline, Audit และข้อมูลที่ตรวจสอบได้
- ห้ามนำ Control หรือข้อมูลภายในของ Back Office ไป Render ใน Member Portal

## 5. Design Tokens

### 5.1 สี

| Token | ค่าเริ่มต้น | วิธีใช้ |
|---|---:|---|
| `canvas` | `#F7F5F0` | พื้นหลังหลักโทนอุ่นคล้ายกระดาษ/หินธรรมชาติ |
| `surface` | `#FFFFFF` | Form, Table, Document และพื้นที่เนื้อหา |
| `ink` | `#121713` | ข้อความหลักและปุ่มหลัก สีดำอมเขียวเล็กน้อย |
| `muted` | `#6F726D` | Metadata, Hint และข้อความรอง |
| `line` | `#D9D7D0` | Divider และ Border 1px |
| `soft` | `#ECE9E1` | Selected Row, Secondary Surface และ Empty State |
| `brand` | `#9A6B2F` | Accent ของ GISP ใช้ไม่เกินประมาณ 5–8% ของหน้า |
| `success` | `#2E6B55` | ผ่าน/อนุมัติ/พร้อมดำเนินการ |
| `warning` | `#9A6A16` | รอตรวจ/ใกล้ครบกำหนด/ต้องระวัง |
| `danger` | `#A33A2B` | ปฏิเสธ/ผิดพลาด/Blocked |
| `info` | `#355F7A` | ข้อมูลและสถานะกำลังดำเนินการ |

กฎ:

- หนึ่ง Surface ใช้สีพื้นหลักไม่เกิน 3 ระดับ
- สีสถานะต้องมีข้อความหรือ Icon ร่วมด้วย ห้ามสื่อความหมายด้วยสีอย่างเดียว
- ห้ามใช้สี Accent กับทุกปุ่ม เพราะจะทำให้ทุก Action ดูสำคัญเท่ากัน
- เอกสารทางการและหน้าพิมพ์ใช้ขาว ดำ และเทาเป็นหลัก

### 5.2 Typography

ใช้ Font ที่รองรับภาษาไทยและมีสิทธิ์ใช้งานชัดเจน ไม่พึ่ง Font เชิงพาณิชย์จากเว็บไซต์อ้างอิง

| หน้าที่ | Font แนะนำ | ลักษณะ |
|---|---|---|
| Display / Editorial | `Noto Serif Thai` | น้ำหนัก 400–600, ใช้กับชื่อหน้าและช่วงเล่าเรื่อง |
| UI / Data / Form | `Noto Sans Thai` | น้ำหนัก 400–700, อ่านตัวเลขและสถานะได้ชัด |
| Number / Document | `Noto Sans Thai` พร้อม `font-variant-numeric: tabular-nums` | ตัวเลขเรียงแนวเดียวกัน |

Type Scale แบบ Comfortable 16px:

- Marketing Display: 48–72px Desktop, 36–48px Tablet, 30–38px Mobile
- Application Page Title: 40–58px Desktop, 36–48px Mobile
- Section Title: 28–32px
- Card/List Title: 20–24px
- Application Body และคำอธิบาย: 16px, Line-height 1.65–1.75
- Sidebar และรายการข้อมูล: 15px
- Form Input/Select: 16px; Form Label: 14px
- Primary Action: 15px; Compact Action: 14px
- Helper Text: 13–14px
- Eyebrow/Metadata/Status/Metric Label: 12px, Letter-spacing `0.10em–0.16em`
- Metric Value: 28–36px

กฎ:

- ใช้ Serif เฉพาะจุดสำคัญ ไม่ใช้กับตารางหรือ Form จำนวนมาก
- Label ตัวพิมพ์ใหญ่แบบเว็บไซต์อ้างอิงใช้กับภาษาอังกฤษเท่านั้น ภาษาไทยใช้ข้อความสั้นและ Letter-spacing ปกติ
- ข้อความที่จำเป็นต่อการทำงานห้ามต่ำกว่า 14px; ใช้ 12px ได้เฉพาะ Metadata, Status และข้อความตกแต่งที่ไม่ใช่ Action
- ห้ามใช้ตัวอักษรต่ำกว่า 12px ใน Member Application และ Back Office
- รักษาพื้นที่ว่างแบบ Minimal ด้วยการลดองค์ประกอบ ไม่ใช่ลดขนาดตัวอักษร
- จำนวนเงินใช้ Tabular Number และจัดชิดขวาเสมอ

### 5.3 Spacing และสัดส่วน

- Base Unit: 8px
- ระยะภายใน Control: 12–16px
- ระหว่าง Field: 20–24px
- ระหว่างกลุ่มข้อมูล: 32–48px
- ระหว่าง Editorial Section: 72–120px
- Application Content Width: สูงสุด 1440px
- Reading/Document Width: 720–880px
- Desktop Page Padding: 40–64px
- Tablet Page Padding: 24–32px
- Mobile Page Padding: 16–20px

### 5.4 รูปทรง เส้น และเงา

- Radius พื้นฐาน 0–4px; Panel ใหญ่ไม่เกิน 8px
- Button หลักเป็นสี่เหลี่ยมมุมตรงหรือมนเล็กน้อย
- Border 1px สี `line`
- Shadow ใช้เฉพาะ Overlay/Drawer: เบาและกระจาย ไม่ดำเป็นก้อน
- Card สินค้าใช้ภาพและ Typography แบ่งชั้น ไม่ต้องมีกรอบรอบทุกใบ
- Status Badge ใช้ Radius 2–4px ไม่ทำเป็น Bubble ขนาดใหญ่

### 5.5 ภาพ

- Product Image: 4:5 หรือ 1:1 ตามประเภทสินค้า พื้นหลังสะอาด
- Editorial/Project Image: 3:2, 16:9 หรือ Full-bleed
- Material Swatch: สีและ Texture ต้องเที่ยงตรง ห้ามใส่ Filter จัด
- ใช้ `object-fit: cover` ในภาพบรรยากาศ และ `contain` ในภาพสินค้า/เอกสารที่ห้ามถูกตัด
- มี Alt Text ที่บอกสินค้า วัสดุ หรือบริบทจริง
- ภาพ Demo ต้องมีคำว่า `DEMO` หรือคำอธิบายว่าเป็นข้อมูลจำลอง

## 6. Layout System

### 6.1 Global Header

- Desktop สูงประมาณ 88–104px; Mobile 64–72px
- Logo ซ้าย, Navigation หลักอยู่กึ่งกลางหรือด้านซ้ายตามพื้นที่, Utility ด้านขวา
- ใช้พื้นขาวหรือ Transparent เหนือภาพได้เฉพาะหน้า Editorial
- Header แบบ Transparent ต้องเปลี่ยนสี Logo/ข้อความตาม Contrast และเปลี่ยนเป็นพื้นทึบเมื่อ Scroll
- Primary CTA เป็นปุ่มสี `ink` ตัวอักษรขาวทรงเหลี่ยม
- Application Header ต้องแสดง Account, Notification และ Environment/Demo Label อย่างชัดเจน

### 6.2 Member Application Shell

- Desktop ใช้ Header + Navigation ที่โปร่งและอ่านง่าย; เมื่อหน้ามี Workflow ยาวให้ใช้ Sidebar หรือ Sub-navigation
- Home/Catalog/Product Detail ใช้ภาพและพื้นที่ว่างมากกว่าหน้าธุรกรรม
- Orders/Payments/QC/Claims ใช้ Content Grid และ Summary Rail ไม่ใช้ Hero Image ขนาดใหญ่
- Action Required แสดงด้านบนแบบรายการลำดับความสำคัญ ไม่ทำ Dashboard Card สีสดหลายใบ

### 6.3 GISP Back Office Shell

- Sidebar กว้าง 240–272px พื้น `ink` หรือขาว ขึ้นอยู่กับ Contrast ของ Content
- Top Utility Bar สูง 64–72px สำหรับ Search, Role Context, Notification และ Account
- Main Canvas ใช้พื้น `canvas`; พื้นที่ทำงานใช้ `surface`
- Sticky Page Header มีชื่อหน้า สถานะ จำนวนรายการ และ Primary Action เดียว
- ตารางต้องเป็นแกนหลักของ Master Data; Detail เปิดเป็นหน้าเต็มหรือ Side Panel ตามความซับซ้อน
- ห้ามใช้ Banner ภาพใหญ่ในหน้าการเงิน, Permission, QC หรือ Logistics

### 6.4 Grid

- Desktop: 12 Columns
- Tablet: 8 Columns
- Mobile: 4 Columns
- Product Grid: 4 คอลัมน์ Desktop, 2–3 Tablet, 1–2 Mobile
- Dashboard Summary: 4 คอลัมน์สูงสุด แต่ต้องรวมตัวเลขที่เกี่ยวข้อง ไม่สร้าง Card แยกทุก Metric
- Form ยาวใช้ 2 คอลัมน์เฉพาะ Field ที่เกี่ยวข้อง; Mobile เป็น 1 คอลัมน์

## 7. Component Instructions

### 7.1 Button

- Primary: พื้น `ink`, ตัวอักษรขาว, Border `ink`, สูงอย่างน้อย 44px
- Secondary: พื้นโปร่ง, Border `ink`, ตัวอักษร `ink`
- Tertiary: Text Button พร้อมเส้นใต้หรือ Arrow
- Destructive: ใช้สี `danger` และต้องมี Confirmation/Reason ตาม Business Rule
- หนึ่ง Section มี Primary Action เดียว
- Hover ใช้การกลับสีหรือเปลี่ยน Contrast ไม่ใช้ Bounce
- Disabled ต้องเห็นเหตุผล เช่น “รอ Finance ยืนยัน Deposit” ไม่ใช่แค่ปุ่มเทา

### 7.2 Form

- Label อยู่เหนือช่องกรอกเสมอ
- Input สูงอย่างน้อย 44px, พื้นขาว, Border 1px, Radius 0–4px
- Focus Ring 2px ที่เห็นชัดและไม่ถูกตัด
- Helper/Error Text อยู่ใต้ Field และอธิบายวิธีแก้
- Form Section ใช้หัวข้อ Serif เล็กน้อยร่วมกับ Divider
- File Upload ต้องแสดงชนิดไฟล์ ขนาด สถานะ และระดับความลับ

### 7.3 Product Card

- ภาพเป็นพื้นที่หลัก ไม่มีกรอบหนาหรือเงา
- ลำดับข้อความ: Category/Brand → Product Name → Member Price → Suggested Resale/Freight Estimate ตามสิทธิ์
- Status เช่น `PUBLISHED`, `ACTIVE PRICE`, `SAMPLE AVAILABLE` เป็นข้อความขนาดเล็กที่อ่านได้
- Hover เปลี่ยนภาพรองหรือ Zoom ไม่เกิน `1.02`
- Member View ห้ามมี Factory Cost, Formula, Margin, Supplier Identity ที่ยังล็อก หรือ Internal Note อยู่ใน DOM

### 7.4 Data Table

- Header 12–13px น้ำหนัก 600–700, พื้นขาวหรือ `soft`
- Row สูง 52–64px, มี Divider บาง ไม่มีเส้นกริดทุกด้าน
- ชื่อรายการอยู่ซ้าย จำนวนและเงินอยู่ขวา Status อยู่ตำแหน่งคงที่
- Row Action อยู่ขวาสุดและแสดงเฉพาะสิทธิ์ที่ทำได้
- มี Empty, Loading, Error และ No Permission State ครบ
- Mobile แปลงเป็น Structured List หรือให้ Scroll เฉพาะตาราง ห้ามทำทั้งหน้าล้น

### 7.5 Status และ Action Required

- Status ใช้สี + Icon + ข้อความ
- Action Required ต้องบอก: สิ่งที่ต้องทำ, รายการต้นทาง, ผู้รับผิดชอบ, Due Date และผลหากไม่ทำ
- รายการเร่งด่วนเรียงตาม Business Priority และ Due Date
- คลิกแล้วไป Record ต้นทางโดยตรง
- ห้ามสร้าง Generic Task Center นอก Core MVP

### 7.6 Timeline และ Audit

- ใช้เส้นแนวตั้งบางและ Dot ขนาดเล็ก
- แสดง Event, Actor, Timestamp, Before/After และ Reason ตามสิทธิ์
- Member เห็นเฉพาะ Event ที่เปิดเผยได้
- Correction/Reinspection ต้องเป็น Event ใหม่ ห้ามเขียนทับประวัติเดิม

### 7.7 Document Preview

- ใช้พื้นขาว สัดส่วนกระดาษจริง และเงาบางเฉพาะ Preview
- Header เอกสารเรียบ มี Logo GISP, Document Number, Status และ Version
- จำนวนเงินแยก Subtotal, VAT Rate Snapshot, VAT Amount และ Grand Total ชัดเจน
- ปุ่ม Print/Save PDF อยู่นอกพื้นที่เอกสาร
- Member-safe Selector ต้องทำงานก่อน Render และก่อน Download

### 7.8 Modal, Drawer และ Notification

- ใช้ Modal เฉพาะการยืนยันสั้น ๆ หรือ Action ที่เสี่ยง
- งานแก้ไขหลาย Field ใช้ Page หรือ Drawer ไม่ยัดลง Modal เล็ก
- Drawer กว้าง 480–640px บน Desktop และเต็มจอบน Mobile
- Notification ใช้ข้อความสั้น มี Action ที่ชัด และไม่บัง Primary Control

## 8. Motion และ Interaction

- Page/Section Fade: 200–350ms
- Navigation/Drawer: 160–240ms
- Hover Image Crossfade: 250–400ms
- Stagger ของรายการ: ไม่เกิน 40–60ms ต่อชิ้น และไม่เกิน 5 ชิ้น
- ใช้ Ease ที่นุ่ม เช่น `cubic-bezier(0.22, 1, 0.36, 1)`
- ห้ามใช้ Animation ที่ทำให้หน้าเป็นสีขาวรอนานก่อนอ่านข้อมูลได้
- ห้ามใช้ Parallax หนักในหน้าธุรกรรม
- เมื่อเปิด `prefers-reduced-motion` ต้องปิด Fade, Zoom และ Slide ที่ไม่จำเป็น
- Feedback ของการ Save/Approve/Verify ต้องเกิดทันทีและบอกสถานะสำเร็จหรือวิธีแก้ไข

### 9.4 Project Builder

- Header แสดง Project, End Customer และสถานะ

## 10. Responsive และ Accessibility

- Breakpoint อ้างอิง: Mobile `< 640`, Tablet `640–1023`, Desktop `≥ 1024`
- Control มาตรฐานสูง 48–52px; Compact Control และ Touch Target ต้องไม่น้อยกว่า 44×44px
- Sidebar Desktop กว้างประมาณ 284px และ Mobile Drawer ต้องแสดงชื่อเมนูเต็มโดยไม่ตัด Ellipsis
- Keyboard ใช้งาน Navigation, Form, Dialog, Table Action และ File Control ได้ครบ
- Focus State ต้องเห็นชัดทุก Control
- Text Contrast อย่างน้อย WCAG AA
- ไม่ใช้ภาพเป็นพื้นหลังหลังข้อความโดยไม่มี Overlay/Contrast ที่ผ่านเกณฑ์
- Desktop Sidebar ย่อเป็น Drawer บน Mobile; ไม่แสดงเมนูทั้งหมดเป็นแถบยาวแนวนอน
- Table ต้องไม่ทำให้ `body` ล้นแนวนอน
- Error Message ต้องเชื่อมกับ Field และ Screen Reader อ่านได้
- Dynamic Status ใช้ `aria-live` อย่างเหมาะสม

## 11. Performance Rules

- Hero Image ใช้ Responsive Image และกำหนดขนาดล่วงหน้าเพื่อลด Layout Shift
- Product Grid โหลดภาพตาม Viewport และใช้ Thumbnail ที่เหมาะสม
- หน้าแรกต้องเริ่มอ่านเนื้อหาได้โดยไม่รอ Animation
- หลีกเลี่ยง Video Background ใน Core MVP เว้นแต่มีเหตุผลและผ่าน Performance Test
- Font ใช้เฉพาะ Weight ที่จำเป็นและมี Fallback ภาษาไทย
- Skeleton ใช้รูปทรงใกล้เคียง Content จริง ไม่ทำ Shimmer รุนแรง

## 12. Do / Don't

### Do

- ใช้ภาพคุณภาพสูงหนึ่งภาพเป็นจุดนำสายตา
- ใช้ Serif สร้างบรรยากาศ และ Sans-serif ทำงานจริง
- ใช้พื้นที่ว่าง เส้นบาง และ Alignment ที่แม่นยำ
- ทำ Primary Action ให้ชัดเพียงหนึ่งจุดต่อบริบท
- แสดงเหตุผลเมื่อ Action ถูก Block
- รักษา Member-safe Data ตั้งแต่ Selector ไม่ใช่ซ่อนด้วย CSS
- ใช้ Snapshot และ Audit ให้มองเห็นความน่าเชื่อถือของระบบ

### Don't

- อย่าคัดลอก Logo, ภาพ, Copy หรือโค้ดจากเว็บอ้างอิง
- อย่าทำทุกข้อมูลเป็น Card มุมมน
- อย่าใช้ Gradient, Glow, Shadow หนัก หรือสีทองเต็มหน้า
- อย่าลด Font ให้เล็กมากเพื่อให้ดู Minimal
- อย่าใช้ Hero Image ขนาดใหญ่ในหน้าทำงานหลังบ้าน
- อย่าซ่อนข้อมูลสำคัญไว้หลัง Hover อย่างเดียว
- อย่าใส่ Animation ก่อนผู้ใช้จะอ่านหรือทำงานได้
- อย่าเพิ่ม Feature นอก Core MVP เพียงเพื่อเติมพื้นที่หน้าจอ

3. Primary Task หนึ่งอย่างของหน้า
4. ข้อมูล Internal ที่ต้องป้องกัน
5. State, Guard และ Business Rule จาก Master Plan
6. Desktop/Tablet/Mobile Layout
7. Loading, Empty, Error, No Permission และ Blocked State
8. Acceptance Criteria ที่ตรวจได้

## 14. Visual Acceptance Checklist

หน้าใหม่ถือว่าผ่านเมื่อทุกข้อเป็นจริง:

- [ ] หน้าจอให้ความรู้สึก Modern, Minimal, Calm และ Premium โดยไม่คัดลอกแบรนด์อ้างอิง
- [ ] Primary Task และ Primary Action เห็นได้ภายในไม่กี่วินาที
- [ ] ใช้ Color, Type, Spacing, Radius และ Divider ตาม Token
- [ ] ไม่มี Gradient, Shadow หนัก, Card ซ้อนหลายชั้น หรือ Pill เกินจำเป็น
- [ ] จำนวนเงิน สถานะ ผู้รับผิดชอบ และขั้นตอนถัดไปอ่านได้ชัด
- [ ] Member Portal ไม่มี Internal Control หรือ Internal Data ใน DOM/Document/Download
- [ ] Desktop 1440px, Tablet 768px และ Mobile 390px ไม่มีหน้าล้น
- [ ] ใช้ Keyboard ได้ครบและ Focus State เห็นชัด
- [ ] Contrast ผ่าน WCAG AA และไม่สื่อสถานะด้วยสีอย่างเดียว
- [ ] Motion ไม่ขัดขวางการอ่านและรองรับ Reduced Motion
- [ ] Loading, Empty, Error, No Permission และ Blocked State ครบ
- [ ] Business Rule ตรงกับ `MVP BUSINESS MASTER PLAN.md`
- [ ] ไม่มี Feature นอก Core MVP ถูกเพิ่มจากการตีความงานภาพ

## 15. ข้อสรุปสำหรับ GISP

สิ่งที่ควรนำมาจาก Euro Creations คือ **ความสงบ ความมั่นใจ ภาพที่มีคุณภาพ Typography ที่มีลำดับ และการใช้พื้นที่ว่างอย่างมีวินัย** ไม่ใช่การทำทุกหน้าของ GISP ให้เหมือนเว็บไซต์ประชาสัมพันธ์

ผลลัพธ์ที่ต้องการคือ:

- Member รู้สึกว่ากำลังเลือกและสั่งสินค้าภายในระดับมืออาชีพ
- ทีม GISP ทำงานได้เร็ว เห็นสิ่งที่ต้องทำ และตรวจสอบย้อนหลังได้
- ทั้งสอง Portal ดูเป็นแบรนด์เดียวกัน แต่ความหนาแน่นของข้อมูลเหมาะกับหน้าที่ของผู้ใช้
- ความสวยงามไม่ลด Permission, Audit, Snapshot, Payment Gate หรือ Dispatch Gate ที่เป็นหัวใจของ MVP
